## 0. 一句话讲清你的网站是怎么来的

你的博客**不是一个网站程序**，而是一台"把文字变成网页的印刷机"：

```
你在 source/_posts/ 里写 Markdown 文章
        ↓  运行 hexo generate（打稿）
   public/ 里生成一堆 .html 网页
        ↓  推送到 st4awber.github.io（发行）
   https://st4awber.github.io 所有人能看到
```

- **仓库 A：`st4awber-hexo-source`** —— 这是"原稿 + 印刷机"。文章、配置、主题都在这里。
  这就是你问的"项目库"是什么了：**它是你博客的源码仓库，不是另一个网站。**
  它在 GitHub 上（现在是公开的），仓库里的 `themes/butterfly` 是一个"子模块"，
  所以当初在网页上直接下载压缩包时，主题文件夹是空的——这也是它看起来"少了东西"的原因。
- **仓库 B：`st4awber.github.io`** —— 这是"印出来的书"。里面全是自动生成的 HTML/CSS/JS。
  **这个仓库不要手动改**，因为下次生成会把你的手改覆盖掉。
- **`E:\blog`（你电脑上这个文件夹）** —— 就是仓库 A 的本地副本，我已经帮你还原好了。

## 2. 在你电脑上怎么用（三个命令，记住就够了）

打开 PowerShell，先进入文件夹：

```powershell
cd E:\blog
```

| 想干什么 | 命令 |
|---|---|
| **本地预览**（改完先自己看效果） | `npx hexo server` 然后浏览器开 http://127.0.0.1:4000/ |
| **只生成网页**（检查有没有报错） | `npx hexo generate` |
| **清空重来**（改配置后感觉不对劲时用） | `npx hexo clean` |

> 预览服务器会一直占用那个窗口。想关掉就按 `Ctrl + C`。
> 改文章时**不用重启**，保存后刷新浏览器即可（改 `_config.yml` 这类配置才需要重启）。

## 3. 怎么发一篇新文章（你最常用的操作）

### 方法一：用命令创建（推荐，会自动带好开头信息）

```powershell
cd E:\blog
npx hexo new "我的第一篇文章"
```

然后去 `E:\blog\source\_posts\` 找到 `我的第一篇文章.md`，用任意文本编辑器（VS Code、记事本都行）打开，
文件开头长这样：

```markdown
---
title: 我的第一篇文章
date: 2026-09-18 18:30:00
tags:
categories:
---
```

在下面开始写正文即可。**开头这两条横线之间的部分叫 front-matter（文章设置）**，常用写法：

```markdown
---
title: 我的第一篇文章
date: 2026-09-18 18:30:00
updated: 2026-09-20 10:00:00
categories:
  - 生活随笔
tags:
  - 记录
  - 心情
description: 一句话介绍这篇文章，会显示在首页摘要里
cover: /img/bg.avif        # 这篇文章的封面图（可选）
---
```

**分类 vs 标签的区别**（新手最容易混）：

- **分类（categories）**：像书架，一篇文章**主要属于**哪一类。写 `生活随笔`，网址会多一层目录。
- **标签（tags）**：像关键词，一篇可以贴很多个。用来"横向"聚合相关文章。
- 只想要一个就只写一个，都留空也可以（会归到默认分类 `uncategorized`）。

### 方法二：直接在 GitHub 网页上写（不用开电脑）

仓库 A → `source/_posts/` → **Add file → Create new file** → 文件名写 `英文或拼音.md` →
粘贴上面的 front-matter 和正文 → **Commit changes**。
提交后 Actions 会自动构建发布，1~2 分钟后网站就更新了。

### Markdown 最常用的 6 个写法

```markdown
# 一级标题（文章内一般用 ## 和 ###）
## 二级标题
**加粗**   *斜体*   [链接文字](https://example.com)
- 无序列表项
1. 有序列表项
> 引用文字
![图片说明](/img/图片名.jpg)     ← 图片要先放到 E:\blog\source\img\
```

代码块用三个反引号包起来，指定语言会有语法高亮：

````markdown
```python
print("hello")
```
````

## 4. 让网站"自动更新"：已经配好的机制

我给你加的工作流文件是 `E:\blog\.github\workflows\deploy.yml`。它的逻辑是：

```
你把改动 push 到 st4awber-hexo-source 的 master 分支
        ↓ （GitHub 服务器自动，约 1 分钟）
npm ci → hexo generate → 把 public/ 推送到 st4awber.github.io 的 main 分支
        ↓
https://st4awber.github.io 更新完成
```

另外它还带了一个**定时任务**：每年 1/4/7/10 月的 1 号自动重建一次，
这样即使你很久不发文，也能保证自动化流程没有"生锈"。

**还差最后一步（需要你操作一次）**：工作流需要一个令牌才能把结果推到你的网站仓库。
见下一节。

## 5. 【需要你做】配置令牌，让自动发布真正生效

其实总共只有两步，做完以后一辈子都不用再管。

### 第 1 步：创建一个令牌（Personal Access Token）

1. 浏览器打开 https://github.com/settings/personal-access-tokens/new
2. **Token name**：填 `hexo-deploy`
3. **Expiration**：建议选 1 年（到期后重新生成一个换掉即可）
4. **Repository access**：选 **Only select repositories**，勾选这两个：
   - `st4awber/st4awber-hexo-source`
   - `st4awber/st4awber.github.io`
5. **Permissions** → **Repository permissions**，设置两项：
   - `Contents` → **Read and write**
   - `Workflows` → **Read and write**（因为工作流文件本身要提交）
   其余保持 No access。
6. 点 **Generate token**，页面上会出现一串 `github_pat_` 开头的字符串。
   ⚠️ **这串字符只显示一次**，请立刻复制。

### 第 2 步：把令牌存成仓库的 Secret

1. 打开 https://github.com/st4awber/st4awber-hexo-source/settings/secrets/actions
2. 点 **New repository secret**
3. **Name** 填：`DEPLOY_TOKEN`（必须一字不差，大小写敏感）
4. **Secret** 粘贴刚才那串令牌
5. 点 **Add secret**

> 为什么要放 Secret 而不是写进代码？因为代码仓库是公开的，
> 令牌写进文件等于把家门钥匙贴在门上。Secret 只有 Actions 运行时才读得到，日志里也会自动打码。

做完这两步告诉我，我会帮你把源码推回仓库并触发一次部署，验证整条链路通不通。

## 6. 怎么确认"自动更新"成功了

1. 打开 https://github.com/st4awber/st4awber-hexo-source/actions
2. 应该能看到一条叫 **自动构建并发布博客** 的运行记录：
   - 🟡 黄色小圆点 = 正在跑（等一会儿）
   - ✅ 绿色勾 = 成功
   - ❌ 红色叉 = 失败 → 点进去看哪一步红了，把报错发我
3. 成功后打开 https://st4awber.github.io ，页面应该已经是新的了
   （浏览器有缓存的话按 `Ctrl + F5` 强制刷新）

## 7. 各文件是干什么的（改配置前先来这里查）

```
E:\blog\
├─ _config.yml              【站点总配置】网站名、作者、网址、永久链接格式
├─ _config.butterfly.yml    【主题配置】菜单、头像、背景、评论、搜索…（你最常改这个）
├─ package.json             依赖清单 + 快捷命令
├─ .github\workflows\
│   └─ deploy.yml           自动构建发布的流水线
├─ scaffolds\               新建文章时的模板（想统一文章格式就改这里）
├─ source\                  【你自己的内容，全部放这里】
│   ├─ _posts\              文章（.md）
│   ├─ about\index.md       「关于」页面
│   ├─ links\index.md       「友链」页面
│   ├─ categories\index.md  分类页面（自动汇总）
│   ├─ tags\index.md        标签页面（自动汇总）
│   ├─ css\custom.css       你的自定义样式
│   ├─ js\                  你的自定义脚本（光标拖尾、动态背景）
│   └─ img\                 你的图片（背景、头像、favicon）
├─ themes\butterfly\        主题（不要改，升级会被覆盖）
└─ public\                  【自动生成】发布用的网页，不用管也别手改
```

**改配置的原则**：只改 `_config.yml`、`_config.butterfly.yml`、`source\` 里的东西。
要改主题样式，写在 `source\css\custom.css` 里覆盖，别去动 `themes\`。

## 8. 小词典（新手专用）

| 名词 | 白话解释 |
|---|---|
| **Hexo** | 静态博客生成器。读 Markdown → 吐 HTML。你网站的"印刷机" |
| **Butterfly** | 主题，决定网站长什么样（配色、布局、卡片） |
| **Node.js / npm** | Hexo 的运行环境 / 它的"应用商店"，`npm install` 就是按清单下载零件 |
| **Markdown（.md）** | 用符号写格式的纯文本，比如 `**粗体**`、`# 标题` |
| **front-matter** | Markdown 文件开头两条 `---` 之间的设置区（标题、日期、标签） |
| **permalink（永久链接）** | 文章网址，由 `_config.yml` 里的 `permalink` 规则 + 日期 + 文件名决定 |
| **generate / 构建** | 把 Markdown 和模板编译成最终 HTML 的过程 |
| **deploy / 部署** | 把生成的 HTML 推送到线上服务器 |
| **push / 推送** | 把本地改动上传到 GitHub |
| **commit / 提交** | 给改动打一个"存档点"并写说明 |
| **仓库（repo）** | GitHub 上的项目文件夹（带完整历史记录） |
| **Actions** | GitHub 免费提供的"云机器人"，可以自动帮你跑构建和发布 |
| **Secret** | 仓库里加密保存的敏感信息（如令牌），只有 Actions 能读 |
| **PAT / 令牌** | Personal Access Token，一串代表你身份的密码，可随时吊销 |
| **子模块（submodule）** | 一个仓库里"链接"到另一个仓库的目录。压缩包里会缺失，必须单独下载 |
| **CDN** | 别人家的服务器帮你托管公共库（如字体图标），加快加载 |
| **本地预览** | 只在你电脑上跑起来的网站，别人看不到，用来改完先自己看效果 |

## 10. 遇到问题怎么办

| 现象 | 常见原因 / 处理 |
|---|---|
| `npx hexo server` 报端口占用 | 换个端口：`npx hexo server -p 4001` |
| 页面样式全乱 | `npx hexo clean` 后重新 `npx hexo generate` |
| 新文章网址和预期不一样 | 检查文件开头有没有写 `date:`，以及 `_config.yml` 的 `permalink` |
| Actions 红了 | 点进失败的那一步看日志；最常见是 `DEPLOY_TOKEN` 名字拼错或权限不足 |
| 改了没生效 | 网页按 `Ctrl + F5`；或确认代码真的 push 上去了 |
| 图片不显示 | 图片必须放在 `source\img\`，引用写 `/img/文件名` |
