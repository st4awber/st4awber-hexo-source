## 0. 一句话讲清你的网站是怎么来的

你的博客**不是一个网站程序**，而是一台"把文字变成网页的印刷机"：

```
你在 source/_posts/ 里写 Markdown 文章
        ↓  运行 hexo generate（打稿）
   public/ 里生成一堆 .html 网页
        ↓  推送到 st4awber.github.io（发行）
   https://st4awber.github.io 所有人能看到
```

- **仓库 A：`st4awber-hexo-source`** —— 这是"原稿 + 印刷机"。文章、配置、主题都在这里。
  这就是你问的"项目库"是什么了：**它是你博客的源码仓库，不是另一个网站。**
  它在 GitHub 上（现在是公开的），仓库里的 `themes/butterfly` 是一个"子模块"，
  所以当初在网页上直接下载压缩包时，主题文件夹是空的——这也是它看起来"少了东西"的原因。
- **仓库 B：`st4awber.github.io`** —— 这是"印出来的书"。里面全是自动生成的 HTML/CSS/JS。
  **这个仓库不要手动改**，因为下次生成会把你的手改覆盖掉。
- **`E:\blog`（你电脑上这个文件夹）** —— 就是仓库 A 的本地副本，我已经帮你还原好了。

### 关于网络：git 直连 github.com 有时会失败（已找到可靠替代）

实测情况：

| 通道 | 表现 |
|---|---|
| 浏览器访问 github.com | ✅ 稳定 |
| `api.github.com` | ✅ 稳定 |
| `git` 直连 `github.com:443` | ⚠️ **时好时坏**，可能连续多次超时（`Failed to connect ... after 21s`） |

**这不是你配置错了，是网络抖动。** 本次恢复源码就是靠备用通道完成的：

```powershell
pwsh -NoProfile -File tools\import-via-git-api.ps1
```

它走 `api.github.com`，用 GitHub 官方的 Git 数据接口推送：

1. 逐个文件创建 blob
2. 从零构建完整文件树（**注意：不能用 `base_tree`** ——
   远端 `themes/butterfly` 曾是 gitlink（子模块），与普通文件冲突会报 422）
3. 创建提交（父提交 = 远端当前 HEAD，历史保留）
4. 更新 `master` 分支引用

> 实测要点（都踩过坑）：
> - `/repos/{o}/{r}/import` 接口**已废弃**，返回 404，不要用
> - 建树必须**先建最深目录**，否则父目录引用到空的子树 SHA，GitHub 报 422 `GitRPC::BadObjectState`
> - 只在最后一步更新分支引用，所以中途失败**不会破坏仓库**

日常如果 `publish-changes.ps1` 报连接失败，就用上面这条备用命令。

## 3. 怎么发一篇新文章（你最常用的操作）

### 方法一：用命令创建（推荐，会自动带好开头信息）

```powershell
cd E:\blog
npx hexo new "我的第一篇文章"
```

然后去 `E:\blog\source\_posts\` 找到 `我的第一篇文章.md`，用任意文本编辑器（VS Code、记事本都行）打开，
文件开头长这样：

```markdown
---
title: 我的第一篇文章
date: 2026-09-18 18:30:00
tags:
categories:
---
```

在下面开始写正文即可。**开头这两条横线之间的部分叫 front-matter（文章设置）**，常用写法：

```markdown
---
title: 我的第一篇文章
date: 2026-09-18 18:30:00
updated: 2026-09-20 10:00:00
categories:
  - 生活随笔
tags:
  - 记录
  - 心情
description: 一句话介绍这篇文章，会显示在首页摘要里
cover: /img/bg.avif        # 这篇文章的封面图（可选）
---
```

**分类 vs 标签的区别**（新手最容易混）：

- **分类（categories）**：像书架，一篇文章**主要属于**哪一类。写 `生活随笔`，网址会多一层目录。
- **标签（tags）**：像关键词，一篇可以贴很多个。用来"横向"聚合相关文章。
- 只想要一个就只写一个，都留空也可以（会归到默认分类 `uncategorized`）。

### 方法二：直接在 GitHub 网页上写（不用开电脑）

仓库 A → `source/_posts/` → **Add file → Create new file** → 文件名写 `英文或拼音.md` →
粘贴上面的 front-matter 和正文 → **Commit changes**。
提交后 Actions 会自动构建发布，1~2 分钟后网站就更新了。

### Markdown 最常用的 6 个写法

```markdown
# 一级标题（文章内一般用 ## 和 ###）
## 二级标题
**加粗**   *斜体*   [链接文字](https://example.com)
- 无序列表项
1. 有序列表项
> 引用文字
![图片说明](/img/图片名.jpg)     ← 图片要先放到 E:\blog\source\img\
```

代码块用三个反引号包起来，指定语言会有语法高亮：

````markdown
```python
print("hello")
```
````

## 5. Secret 是怎么配的（已完成，仅供了解）

2. 点 **New repository secret**

4. **Secret** 粘贴令牌（`E:\blog\token.txt` 里那串 `github_pat_...`）
5. 点 **Add secret**

### 触发构建（以后需要手动跑一次时）

1. 打开 https://github.com/st4awber/st4awber-hexo-source/actions
2. 左侧点 **自动构建并发布博客**
3. 右侧点 **Run workflow** → 分支选 `master` → 点绿色 **Run workflow**

> 平时不用手动触发：只要往 `master` 推代码，它就会自动跑。

### 令牌权限说明（以后重新生成令牌时照这个配）

| 权限 | 用途 | 必需？ |
|---|---|---|
| `Contents` → Read and write | 读写两个仓库的文件 | ✅ 必需 |
| `Workflows` → Read and write | 提交工作流文件 | ✅ 必需 |
| `Secrets` → Read and write | 让脚本能自动创建 Secret | 可选（手动配就行） |

### ⚠️ 这次踩过的三个坑（很重要，记住能省几小时）

#### 坑 1：YAML 冒号后面少空格 → 整个站点构建失败

```yaml
serverURL:https://xxx        ❌ 错！整份配置解析失败
serverURL: https://xxx       ✅ 对，冒号后必须有空格
```

后果非常严重：不只是评论不显示，而是**整个网站都构建不出来**：

```
YAMLException: bad indentation of a mapping entry (633:5)
hexo generate → exit=2
```

**YAML 里 `键:值` 和 `键: 值` 是完全不同的东西**，前者会被当成一个奇怪的键名。
以后改任何 `.yml` 文件，冒号后都记得敲一个空格。

#### 坑 2：Vercel 项目重名会自动加后缀，别填错地址

点 Waline 一键部署时，如果 `softpane-comment` 这个名字已经被占用，
Vercel 会新建一个叫 `softpane-comment-4xvg` 的项目。**你的 Waline 在后者。**

怎么区分：打开地址看看是什么
- 看到 **Waline 的评论界面** → 对了
- 看到 **你自己的博客** → 这是博客项目，错了
- 看到 **Vercel 登录页** → 这是预览部署地址，被「部署保护」挡住了

**最快的验证方法**：在地址后面加 `/api/comment?type=count&url=/test`
- 返回 `{"errno":0,...}` → ✅ 服务端正常
- 返回 **404** → 这个地址上没有 Waline（多半是静态站点）
- 返回 **500** → 服务端崩了，通常是没连数据库（见坑 3）

#### 坑 3：连了数据库必须 Redeploy，否则函数一直崩

现象：访问任何路径都返回 `FUNCTION_INVOCATION_FAILED`。

原因：**Vercel 的环境变量只在「部署的时候」注入**。
数据库是后来才连上的，所以当时正在运行的那份部署看不到数据库配置，一启动就崩。

**解决**：连上数据库后，去 **Deployments → 选最新那条 → Redeploy**。

怎么看是不是这个问题：去项目左侧 **Logs**，筛选 `environment:production`，
如果看到 `Error: No valid storage found. Please check your environment`，
就是数据库没生效。重新部署后，日志里应该变成 `200` 加 `SQL: SELECT ...`。

### 怎么验证评论真的存进数据库了

在地址后面拼这个路径（把 `url` 换成你的文章路径）：

```
https://softpane-comment-4xvg.vercel.app/api/comment?type=count&url=/2026/04/14/hello-world/
```

返回 `{"errno":0,"errmsg":"","data":[1]}` —— 中括号里的数字就是评论数。
如果这个数字随你发评论而增加，就说明**真的落库了**，不只是前端显示。

## 8. 各文件是干什么的（改配置前先来这里查）

```
E:\blog\
├─ _config.yml              【站点总配置】网站名、作者、网址、永久链接格式
├─ _config.butterfly.yml    【主题配置】菜单、头像、背景、社交、评论、搜索…（你最常改这个）
├─ package.json             依赖清单 + 快捷命令
├─ .github\workflows\
│   └─ deploy.yml           自动构建发布的流水线
├─ docs\
│   └─ 新手操作手册.md       就是本文件
├─ tools\
│   ├─ publish.ps1          首次推送源码到 GitHub（配置令牌后用一次）
│   ├─ publish-changes.ps1  【日常用】提交并发布你的改动
│   ├─ check-links.ps1      站内死链体检
│   ├─ git-askpass.cmd      推送时临时提供令牌（不含令牌本身）
│   └─ MinGit\              便携版 git（只在本机用，不进仓库）
├─ scaffolds\               新建文章时的模板（想统一文章格式就改这里）
├─ source\                  【你自己的内容，全部放这里】
│   ├─ _posts\              文章（.md）
│   ├─ _data\link.yml       友链数据（友链页面的卡片来源）
│   ├─ about\index.md       「关于」页面
│   ├─ links\index.md       「友链」页面
│   ├─ categories\index.md  分类页面（自动汇总）
│   ├─ tags\index.md        标签页面（自动汇总）
│   ├─ css\custom.css       你的自定义样式
│   ├─ js\                  你的自定义脚本（光标拖尾、动态背景）
│   └─ img\                 你的图片（背景、头像、favicon）
├─ themes\butterfly\        主题（不要改，升级会被覆盖）
└─ public\                  【自动生成】发布用的网页，不用管也别手改
```

**改配置的原则**：只改 `_config.yml`、`_config.butterfly.yml`、`source\` 里的东西。
要改主题样式，写在 `source\css\custom.css` 里覆盖，别去动 `themes\`。

### 三个页面模板的特殊写法

这几个页面的开头必须写对 `type`，否则不会按预期渲染：

| 页面 | 文件 | front-matter 必须包含 |
|---|---|---|
| 友链 | `source\links\index.md` | `type: link`（**单数**，写成 `links` 会失效） |
| 分类 | `source\categories\index.md` | `type: categories` |
| 标签 | `source\tags\index.md` | `type: tags` |
| 关于 | `source\about\index.md` | 不需要 `type` |

### 怎么加友链

只改一个文件：`source\_data\link.yml`。里面每一项的 4 个字段：

```yaml
    - name: 对方站点名
      link: https://对方的网址
      avatar: https://对方的头像图片地址
      descr: 一句话简介
```

复制这 4 行，粘贴到 `link_list:` 下面，改内容即可。
**缩进必须用空格**（不能用 Tab），改完保存 → 刷新预览即可看到新卡片。

### 怎么加社交图标

改 `_config.butterfly.yml` 的 `social:` 段，一行一个，格式是
`图标类名: 链接 || 悬浮文字 || 颜色`：

```yaml
social:
  fab fa-github: https://github.com/st4awber || GitHub || '#24292e'
  fas fa-envelope: mailto:3367056854@qq.com || Email || '#4a7dbe'
  fab fa-bilibili: https://space.bilibili.com/你的ID || Bilibili || '#00a1d6'
```

图标类名可以在这里查：https://fontawesome.com/search （找免费版里有的）

## 9. 小词典（新手专用）

| 名词 | 白话解释 |
|---|---|
| **Hexo** | 静态博客生成器。读 Markdown → 吐 HTML。你网站的"印刷机" |
| **Butterfly** | 主题，决定网站长什么样（配色、布局、卡片） |
| **Node.js / npm** | Hexo 的运行环境 / 它的"应用商店"，`npm install` 就是按清单下载零件 |
| **Markdown（.md）** | 用符号写格式的纯文本，比如 `**粗体**`、`# 标题` |
| **front-matter** | Markdown 文件开头两条 `---` 之间的设置区（标题、日期、标签） |
| **permalink（永久链接）** | 文章网址，由 `_config.yml` 里的 `permalink` 规则 + 日期 + 文件名决定 |
| **generate / 构建** | 把 Markdown 和模板编译成最终 HTML 的过程 |
| **deploy / 部署** | 把生成的 HTML 推送到线上服务器 |
| **push / 推送** | 把本地改动上传到 GitHub |
| **commit / 提交** | 给改动打一个"存档点"并写说明 |
| **仓库（repo）** | GitHub 上的项目文件夹（带完整历史记录） |
| **Actions** | GitHub 免费提供的"云机器人"，可以自动帮你跑构建和发布 |
| **Secret** | 仓库里加密保存的敏感信息（如令牌），只有 Actions 能读 |
| **PAT / 令牌** | Personal Access Token，一串代表你身份的密码，可随时吊销 |
| **子模块（submodule）** | 一个仓库里"链接"到另一个仓库的目录。压缩包里会缺失，必须单独下载 |
| **CDN** | 别人家的服务器帮你托管公共库（如字体图标），加快加载 |
| **本地预览** | 只在你电脑上跑起来的网站，别人看不到，用来改完先自己看效果 |
| **Vercel / Neon** | 免费托管服务 / 免费数据库，Waline 评论要用到 |

## 11. 遇到问题怎么办

| 现象 | 常见原因 / 处理 |
|---|---|
| **构建报 `YAMLException: bad indentation`** | **改了 `.yml` 文件**，冒号后少空格。`serverURL:https://x` 要写成 `serverURL: https://x`（坑 1） |
| **评论区加载失败 / 一直转圈** | `waline.serverURL` 填错。测 `<地址>/api/comment?type=count&url=/test`：返回 `{"errno":0}` 才对，404 = 不是 Waline，500 = 没连数据库（坑 2、坑 3） |
| **Waline 所有路径都 500** | `FUNCTION_INVOCATION_FAILED` = 没连数据库，或连了数据库但**没 Redeploy**（坑 3） |
| `git push` 卡住/超时 | 网络抖动，改用备用通道 `tools\import-via-git-api.ps1 -Message "说明"` |
| `npx hexo server` 报端口占用 | 换个端口：`npx hexo server -p 4001` |
| 编辑源文件报"文件被占用" | 先按 `Ctrl + C` 关掉预览服务器，改完再开 |
| 页面样式全乱 | `npx hexo clean` 后重新 `npx hexo generate` |
| 新文章网址和预期不一样 | 检查文件开头有没有写 `date:`，以及 `_config.yml` 的 `permalink` |
| 友链页不显示卡片 | 检查 `source\links\index.md` 是否写了 `type: link`（单数） |
| Actions 红了 | 点进失败的那一步看日志；最常见是 `DEPLOY_TOKEN` 名字拼错或权限不足 |
| 改了没生效 | 网页按 `Ctrl + F5`；或确认代码真的 push 上去了 |
| 图片不显示 | 图片必须放在 `source\img\`，引用写 `/img/文件名` |
